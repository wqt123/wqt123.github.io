# WQT Agent Lab 博客重设计规格

日期：2026-08-25

## 目标

把现有博客从“浅绿色卡片式文章首页”重构为一个具有清晰身份和内容层级的个人 Agent 实验室。首页不再直接呈现文章流，而是先回答两个问题：这个站点是什么，以及访客可以从哪类内容进入。

本次重设计服务于一个长期方向：站点未来主要记录智能体相关的学习、构建、沉淀和个人判断。

## 品牌与语气

- 站点名称：`WQT Agent Lab`
- 不显示作者署名或笔名。
- 核心定位：一个 Agent 工程师持续学习、构建和思考的个人工作台。
- 文案应直接、克制、有工程感，不使用营销式口号、虚假成果或装饰性术语。
- 建议首页主句：“和智能体一起，持续构建。”
- 建议辅助文案：“Agent 工程师的个人工作台。记录学习、实验、项目，以及尚未定型的判断。”

## 视觉方向

采用已确认的“A：信号白·编辑实验室”方向。

### 色彩

- 页面背景：真白，不使用浅绿、米白或渐变背景。
- 主文字：深墨色，用于标题和正文。
- 次级文字：中性冷灰。
- 主强调色：靛蓝，用于链接、当前状态和关键结构。
- 次强调色：琥珀，仅用于少量状态标记和信号点。
- 分隔线：低对比度冷灰。

实施时应在单一 token 文件或 CSS `:root` 中定义语义颜色。组件不得散落硬编码颜色。

### 排版与容器

- 视觉性格接近独立技术编辑刊物，而不是 SaaS 仪表盘。
- 标题使用有力量的无衬线字体；正文优先保证中英文长文阅读。
- 使用字号、留白、对齐和细分隔线建立层级。
- 取消大面积圆角容器、胶囊标签、阴影卡片和卡片网格。
- 首页四类入口采用开放式四列结构；桌面端用分隔线组织，移动端自然折叠。
- 不使用装饰性渐变、发光效果或无意义图标。

### 动效

- 只保留一次轻量首屏进入效果，以及链接和分类入口的 hover/focus 状态。
- 动效不能阻碍阅读，且必须支持 `prefers-reduced-motion`。

## 信息架构

### 全局导航

导航保持精简：

1. 内容地图
2. 全部文章
3. 关于
4. GitHub（外部链接）

品牌标识 `WQT Agent Lab` 返回首页。

### 首页

首页只包含以下内容，顺序固定：

1. 站点身份与主宣言。
2. 当前关注方向，例如 Agent 基础设施、上下文工程和安全执行。
3. 四类内容入口。
4. 简洁页脚。

首页明确不包含：

- 最新文章列表；
- 人工精选文章；
- 作者署名；
- 热门排行；
- 文章卡片网格；
- 伪造的文章数量或状态。

### 四个主分类

每篇文章必须且只能选择一个主分类：

1. `notes` / 学习笔记：概念拆解、论文阅读、工具探索。
2. `projects` / 项目实践：真实实现、踩坑记录、工程复盘。
3. `topics` / 深度专题：系统整理后可长期复用的内容。
4. `thoughts` / 随想：行业观察、个人判断和未完成想法。

技术主题继续通过多个标签表达，例如 `Agent`、`图计算`、`大数据`。主分类负责内容形态，标签负责主题检索，两者不可混用。

现有文章《大数据、图计算与 Agent 学习指南》归入“深度专题”。

首页四类入口始终显示。分类无文章时显示“正在积累”，并保留进入分类页的能力；不得生成占位文章。

### 列表页

- 全部文章页和分类页采用编辑式纵向目录。
- 每项显示发布日期、主分类、标题、摘要和技术标签。
- 列表页不显示浏览量。
- 无内容分类页提供清楚的空状态，并返回内容地图。

### 文章页

- 标题区显示主分类、标题、日期、阅读时长和浏览量。
- 浏览量只在文章标题下方出现，不在首页或列表页出现。
- 正文使用收窄的阅读列和稳定的中英文排版。
- 桌面端目录可位于侧栏并保持可见；移动端目录折叠或回到正文流。
- 技术标签位于标题区或文末，保持低视觉权重。
- 评论区位于正文和文末信息之后。

## 内容模型

文章 front matter 增加单值主分类字段，例如：

```toml
category = "topics"
tags = ["Agent", "图计算", "大数据"]
```

Hugo 配置应把主分类注册为单值可用的 taxonomy，或通过等价模板逻辑保证每篇文章只有一个主分类。构建阶段应提供可验证的规则，防止缺少分类或配置多个分类。

## 浏览量统计

使用 GoatCounter：

- 每篇文章按稳定的 canonical pathname 记录浏览量。
- 仅文章页加载计数与展示逻辑。
- 页面展示使用 GoatCounter 官方支持的单页计数能力。
- 计数文字低对比度呈现，例如“123 次阅读”。
- 加载期间显示中性占位符；请求失败或被隐私插件拦截时显示 `—`，不得阻塞正文或产生布局跳动。
- GoatCounter 站点代码和开关通过 Hugo 参数配置，不能硬编码在模板多个位置。
- 本地开发环境默认不记录真实访问，避免污染数据。

## 评论系统

使用 Giscus：

- 评论数据存储在 `wqt123/wqt123.github.io` 的 GitHub Discussions。
- 评论者必须登录 GitHub。
- 文章与 Discussion 使用稳定 pathname 映射，避免标题变化导致评论丢失。
- 评论组件使用简体中文界面，并选择与真白、靛蓝视觉系统协调的浅色主题。
- Giscus 配置集中放在 Hugo 参数中，包括仓库、repo id、category、category id 和映射方式。
- 只在文章页加载 Giscus，不在首页、列表页或关于页加载。
- 脚本加载失败时显示简短说明和前往 GitHub Discussions 的备用入口；正文阅读不受影响。

启用前需要完成两项仓库设置：启用 GitHub Discussions，并为仓库安装/授权 Giscus App。相关 ID 在实施时从 Giscus 配置页取得。

## 响应式与可访问性

- 桌面四列分类在中等宽度变为两列，在窄屏变为单列或清晰的两列，不改变内容顺序。
- 导航在手机上保持可访问，不允许横向溢出。
- 所有交互具有可见键盘焦点。
- 文本和背景满足 WCAG AA 对比度。
- 页面使用语义化标题结构、导航地标和文章元素。
- 第三方 iframe 或脚本必须有合理的加载边界，不能造成主要内容位移。

## 实现边界

- 保留 Hugo、Markdown、GitHub Pages 和现有部署方式。
- 优先重构现有 layouts 与 CSS，不引入 React 或新的前端框架。
- Mermaid 支持继续保留。
- 不在本次范围内增加搜索、订阅系统、用户账户、排行榜或 CMS。
- 不为内容稀少的问题制造假数据或占位文章。

## 验收与验证

实施完成必须执行：

1. Hugo 生产构建成功，无模板或 taxonomy 错误。
2. 首页、全部文章、四个分类、关于页和现有文章链接有效。
3. 已有文章归入“深度专题”，且主分类唯一。
4. 首页不出现精选文章、最近更新、作者署名或文章卡片网格。
5. GoatCounter 仅在生产文章页记录访问；失败状态不影响阅读。
6. Giscus 仅在文章页加载；未配置和加载失败状态可理解。
7. 桌面与移动视口各进行至少两轮截图审查，检查层级、排版、间距、颜色和溢出。
8. 键盘焦点、减少动态效果和正文可读性通过人工检查。
9. 视觉实现与批准的“信号白 + 靛蓝/琥珀”方向进行逐项对照。

## 外部依赖与实施前提

- GoatCounter 需要创建站点并提供站点代码。
- GitHub 仓库需要启用 Discussions，并授权 Giscus App。
- Giscus 的 repo/category ID 需要在外部设置完成后写入配置。
- 在这些值尚未提供时，模板应支持关闭集成并呈现稳定的未启用状态，不得使用伪造 ID。
